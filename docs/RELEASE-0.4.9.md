# EWord 0.4.9：在原位置直接编辑

## 使用变化

- XLSX 不再弹出单元格编辑对话框。单击单元格即可在原方框输入文字、数字或公式。键盘“完成”、上方“完成”、切换单元格或工作表时提交；“另存为”仍导出副本。
- PPTX 不再显示文字列表或修改对话框。直接点页面上的文字段落，在原位置输入；底栏“编辑”也可定位当前页第一段文字。点空白处或“完成”结束编辑，保存时沿用原有副本流程。
- 编辑框随缩放、滚动定位；表格单独处理冻结行列和合并单元格边界。PPT 复用 DeckCraft 的真实文字布局定位，不按文字内容猜测目标，内容相同的文本框也分别识别。
- 中文输入法组词期间不触发空闲自动提交；提交时不重置输入框光标和选区。后台保存只确认实际写入的文本快照，较新的输入继续保留为草稿；迟到的输入回调不能写进另一个单元格。
- 输入空闲约一秒后保存私有工作副本，切换、保存、分享、返回及进入后台时提交待写内容。失败时保留当前输入并提示，不自动覆盖来源文件。

## 保存与格式

PPT 一段文字可能包含多个格式片段。现在将段落作为一个输入框，修改时保留未改动前缀和后缀所在的格式节点，新插入文字继承修改边界的格式。只更新对应页 XML，其余原文件部件继续直接复制。复杂富文本的完整排版编辑不在本次范围内；编辑中的白色输入框是临时界面，不写入文档背景。

旧版 PPT、超过既定大小限制的文件、动态字段等不支持的内容继续保留阅读能力。已有数字签名的 PPT 包仍拒绝修改。原版本恢复、回收站、OCR、翻译、PDF 工具及 Word 编辑流程保留。

## 核验范围

- Rust mobile 测试：50 项通过、1 项忽略。新增相同文字的不同 PPT 文本框定位、整段修改、清空后再次输入、软换行移除、格式节点保留与保存重开测试；原 Word、PDF、签名、扫描、表格和翻译相关静态资产链路继续检查。
- Android 针对性测试：19 项通过，含输入草稿快照、输入法组词、迟到回调、冻结区域和缩放/平移坐标，以及原最近文件、设置开关手势测试。沿用本地排除既有 ReadAloudLanguageTest 编译问题的脚本；不代表 Android 全套单元测试通过。
- 桌面 PowerPoint 实际重开整段修改结果，验证两个文本框的位置、中文和 XML 特殊字符，以及粗体前缀和斜体后缀。
- 手机软键盘、触摸、可视对齐及系统另存的完整流程仍由用户手工验收，未以单元测试代替触屏验收。
